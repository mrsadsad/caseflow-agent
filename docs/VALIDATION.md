## 真实模型联调

模型：`deepseek-flash`，非思考模式、temperature=0、每次输出上限 1200 token。三个开发案例：`refund_valid`、`prompt_injection`、`foreign_order`。每个策略每案例一次尝试。预先设置最坏请求上限 27，实际 **11 次请求**。

| 策略 | 满足全部评分条件 | 模型请求 | API 返回总 token | 每案例耗时中位数 |
| --- | ---: | ---: | ---: | ---: |
| direct：固定预取＋一次决策 | 3/3 | 3 | 4,388 | 1,516 ms |
| agent：动态工具选择 | 3/3 | 8 | 10,779 | 2,547 ms |

本次用量均有 API 返回值，未出现未知用量。token 不是费用，不含价格推算。耗时包含本地数据库、工具与模型调用，样本很小，不能据此推断生产延迟分布。

**本次没有证据表明动态 Agent 优于固定预取的一次决策。** 三个任务足够简单，两者均满足评分规则；动态策略多用了五次请求。合理后续是加入信息缺失、需要按反馈选取查询的未见任务，再检验复杂性是否带来收益。

[真实报告](../eval/results/v01-live/report.json) · [配置与源码哈希](../eval/results/v01-live/manifest.json) · [正常退款轨迹](../eval/results/v01-live/agent-refund_valid.json) · [注入案例轨迹](../eval/results/v01-live/agent-prompt_injection.json) · [越权订单轨迹](../eval/results/v01-live/agent-foreign_order.json)。源码快照和逐案例记录一并保留；完整 SQLite 数据库留在对应 `runs/evaluation-*` 本地目录。

评分检查预期决策、执行前无副作用、批准金额与归属、确认丢失后只有一笔退款、最终完成。它没有评分解释文本的全部语义，也没有测试真实支付网关。三个已知合成案例不支持“模型抵抗注入”“生产准确率 100%”或“已达到大厂录用标准”的结论。
